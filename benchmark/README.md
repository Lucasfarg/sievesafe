# sievesafe benchmark

Everything behind the numbers sievesafe quotes, from public data. `results.md` is generated by `results.py`; no number in
it is typed by hand.

## What is here

| path | what |
|:--|:--|
| `answers/f1-<review>.jsonl.gz` | Jev's answer for every record of the 23 SYNERGY+ test reviews (33,001 calls) |
| `answers/c1-<review>.jsonl.gz` | Jev's answers for the 20 train reviews, capped at 1,000 records each (12,982 calls) |
| `answers/stability-jev-1.13.0.jsonl.gz` | 2,000 test records asked a second time with the model pinned |
| `answers/asreview-3.0.8.json` | reading positions of the included studies in 69 ASReview simulations (23 reviews × 3 seeds) |
| `calibration.json` | the thresholds frozen on the train reviews, with the time and the SHA-256 of the answers used |
| `data-manifest.json` | size, include count and a hash of the labels of each SYNERGY+ review this was run on |
| `results.md` | every table: calibration, test split, leave-one-review-out, title/abstract labels, ASReview, stopping rules, stability, cost |

The answers hold OpenAlex ids, probabilities and token counts only; no titles or abstracts. The SYNERGY+ records themselves
are not redistributed here (their abstracts may not be republished as plain text), so step 1 downloads them.

## Reproduce

From the repository root, Python ≥ 3.11 and [uv](https://docs.astral.sh/uv/):

```bash
# 1. SYNERGY+ v3 into benchmark/data (answers "Y" to converting abstracts to plain text locally; ~3 minutes)
yes Y | SYNERGY_VERSION=3.0 uvx --from synergy-dataset==2.2 --with pandas synergy get -o benchmark/data

# 2. check the calibration: the frozen file is what the train answers give (no API calls)
python3 benchmark/calibrate.py --as-frozen

# 3. regenerate every table from the data and the committed answers (no API calls, a few seconds)
python3 benchmark/results.py
git diff --stat benchmark/results.md        # nothing changes if your data matches data-manifest.json

# 4. the same checks as tests
python3 -m unittest discover -s tests
```

`results.py` refuses to run if the downloaded data differs from `data-manifest.json`. With the data elsewhere, set
`SYNERGY_DATA=/path/to/data` instead of step 1.

### Asking Jev again (spends money)

Needs a TypeSafe key (`TYPESAFE_API_KEY` or `~/.config/sievesafe/typesafe.env`). Each script has a hard `--budget` in US$
that counts the answers already on disk for that variant, and stops before a call could cross it. New answers go to
`answers/*.jsonl` (plain, ignored by git); compress with `gzip -n` to commit them.

```bash
python3 benchmark/screen.py f2 test --budget 1.60                 # every test record, new variant f2: ~US$ 1.55
python3 benchmark/screen.py c2 train --cap 1000 --budget 0.65     # train reviews as calibrated: ~US$ 0.61
python3 benchmark/stability.py --n 2000 --budget 0.15             # ~US$ 0.09
```

A new variant only enters `results.md` after editing `common.TEST` / `common.TRAIN`. A new model or a new question needs
a new calibration (`calibrate.py --write`, then the test split again); sievesafe pins `jev-1.13.0` for this reason.

### ASReview (no API, CPU only)

```bash
uv venv benchmark/.venv-asreview --python 3.12
uv pip install --python benchmark/.venv-asreview asreview==3.0.8
python3 benchmark/asreview_baseline.py        # 69 simulations into benchmark/.asreview/, then answers/asreview-3.0.8.json
```

## Design

- **Data.** SYNERGY+ v3 (114 reviews with published screening decisions). Its own split puts 23 reviews in `test`.
  Labels are the final (full-text) inclusions; 12 test reviews also publish the title/abstract decision (section 4).
- **Question.** One Jev yes/no question per record, zero-shot: the review's title and its SYNERGY+ `eligibility_criteria`
  text, the record's title and abstract, and a policy that favours sending doubtful records to full text. It is the exact
  question `sievesafe screen` asks (`src/sievesafe/jev.py`), and `screen.py` imports it from there.
- **Calibration.** 20 reviews from SYNERGY+'s train split, capped at 1,000 records each (every
  include plus a seeded sample of excludes, weighted back to full size). For each recall target the threshold is the
  highest score that keeps that share of the pooled train includes. Frozen, time-stamped and hashed in `calibration.json`.
- **Known flaw of the frozen calibration.** The frozen run looked scores up by OpenAlex id pooled over the train reviews,
  so papers that appear in two reviews carried the later review's score (`results.md` §1 has the counts). `calibrate.py
  --as-frozen` reproduces the frozen file exactly; `calibrate.py` shows the corrected procedure, whose thresholds are
  higher. sievesafe keeps the frozen, more conservative 0.06: it is the value fixed before the test split was scored, and
  §2 reports the test split at both.
- **Evaluation.** Test split at the frozen thresholds, never retuned; leave-one-review-out over all 43 answered reviews
  for how much the threshold moves between reviews; ASReview 3.0.8 with its defaults as the reference ranking tool.
- **Model.** The f1/c1 answers were asked with model id `jev-latest` in September 2026; the stability run pins
  `jev-1.13.0`, and sievesafe sends that pinned id.
