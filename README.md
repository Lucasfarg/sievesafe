# sievesafe

Title/abstract screening for systematic reviews that only removes records when it is safe to.

You give it your search export and your eligibility criteria. For every record it estimates the probability that the
record should go on to full-text review, with no training and no labelled examples. It then does one of two things:

- **rank** (default): keeps every record, puts the most likely ones first, and flags those below a *safe threshold*;
- **exclude** (opt-in): removes the records below the safe threshold before human screening, and gives you a random
  sample of them to validate on your own review.

Either way you get your records back in the format they came in, ready to import into Rayyan, Covidence, EndNote or
Zotero, plus a report with the PRISMA 2020 count and a methods paragraph.

## What it promises, and what it does not

The safe threshold was frozen on 20 reviews and then tested, unchanged, on 23 others and on Cochrane reviews from
another collection (CLEF TAR). Across all of them **it lost one finally included study, in one review**, while a large
share of all records fell below it; that one record is a cardiology paper listed as included in a colorectal cancer
review, most likely a labelling error, but it counts. That is the promise:
the records it removes are very unlikely to hold a study that ends up in your review.

It does **not** promise to match human title/abstract screening. Some records that human screeners passed on to full
text do fall below the threshold; in the benchmark, all of those were later excluded at full text. And a benchmark is
not a guarantee for your review: before relying on exclude mode, validate it locally (the RAISE recommendations).

## Install

Python 3.11 or newer. With [pipx](https://pipx.pypa.io):

```bash
pipx install sievesafe            # or, from a clone of this repository: pipx install .
```

sievesafe calls [TypeSafe](https://docs.typesafe.ai)'s Jev model, which needs a paid API key. Put it in an environment
variable or in a file:

```bash
mkdir -p ~/.config/sievesafe
echo 'TYPESAFE_API_KEY=your-key' > ~/.config/sievesafe/typesafe.env
chmod 600 ~/.config/sievesafe/typesafe.env
```

## Use

In the browser (a local page; nothing leaves your computer except what is sent to TypeSafe, see below):

```bash
sievesafe serve
```

In the terminal:

```bash
sievesafe screen search.ris --criteria criteria.txt --title "Emicizumab prophylaxis in children with haemophilia A"
sievesafe screen search.ris --criteria criteria.txt --title "…" --mode exclude --budget 1.00
```

It shows the number of records and the estimated cost, and asks before spending. `--budget` is a hard cap in US$:
records it could not score are kept, first in the list, and never removed. Rerunning on the same file costs nothing
for the records already scored.

**Inputs:** RIS (Scopus, Web of Science, Rayyan, EndNote, Zotero…), PubMed/MEDLINE `.nbib`, Web of Science plain text,
and CSV/TSV with `,` or `;` in any common encoding. **Outputs**, in the same format and encoding:

| file | what |
|:--|:--|
| `to-screen.<ext>` | the records for human screening, most likely first, untouched |
| `ranked.csv` | rank, original position, probability, flag and title of every record |
| `excluded.<ext>` | exclude mode: the removed records |
| `validation-sample.<ext>` | exclude mode: 50 of the removed records at random, to screen for local validation |
| `report.md` | counts for the PRISMA 2020 diagram, a methods paragraph, the validation evidence and your criteria |

Records **without an abstract** are ranked but never flagged or removed (the threshold was only validated on records
with abstracts). **Duplicates** (same DOI or title) are scored once and every copy is kept; deduplication stays with your
reference manager.

## Limits

- **Title/abstract stage only.** It does not read full texts, and it is tuned to pass doubtful records on.
- **English-language literature.** Most benchmark reviews restricted their searches to English; other languages are untested.
- **A paid, closed model.** Each record costs a fraction of a cent, and each record's title and abstract, with your
  review title and criteria, are sent to TypeSafe's API. The model is proprietary; sievesafe pins the version
  (`jev-1.13.0`) the threshold was calibrated on. If that version is retired the threshold has to be recalibrated, and
  [`benchmark/`](benchmark/) shows how.
- **Two benchmarks, not a guarantee.** SYNERGY+ and CLEF TAR are public reviews with published criteria. In
  leave-one-review-out tests and in the external sets, the threshold kept every included study in all but one review
  each time (see the tables above).
  Vaguer criteria make it remove fewer records, not lose more studies, in the one test of this (CLEF, objectives only).
- **A known flaw in how the threshold was frozen**, disclosed in [`benchmark/README.md`](benchmark/README.md): the
  correct procedure gives a slightly higher threshold; sievesafe keeps the frozen, more conservative one.

## How it works

One yes/no question per record to Jev, a TypeSafe System One model that returns a probability instead of generated text:
*should this record move on to full-text review for this review?*, with the review's title and criteria, the record's
title and abstract, and a policy that missing a relevant study is far worse than reading an extra one. The answers are
cached on disk by model, criteria and record text. The threshold was frozen on 20 calibration reviews as the
highest probability that kept every one of their included studies.
